# پارسی‌ورد · ParsiWord

نسخهٔ آزمایشی ۰.۲.۴: خروجی اندروید فقط ARM64، ساخت release و بسته‌بندی فشردهٔ کتابخانهٔ بومی با استخراج هنگام نصب. اصلاح جهت علامت‌های متن ترکیبی، گروه‌بندی S11 و فونت جایگزین ۱۴ علامت از ۰.۲.۳ برقرارند. آزمون سخت همچنان ۶۵ جفت استاندارد Unicode 18 و هفت جفت زاویه/نقل‌قول تکمیلی را پوشش می‌دهد. انتخاب Google Fonts و رابط Tailwind 4 و shadcn/ui (Radix) برقرار است.

در «تنظیمات خروجی ← فونت خروجی»، حدود ۱۹۵۰ خانوادهٔ فونت قابل جست‌وجو هستند. فقط خانوادهٔ انتخابی دانلود می‌شود؛ نسخهٔ معمولی و پررنگ آن روی دستگاه نگه داشته می‌شوند و در خروجی DOCX هم جاسازی می‌شوند. وزیرمتن از ابتدا همراه اپ است. گزینهٔ «دانلودشده» و دکمهٔ حذف برای مدیریت حافظه وجود دارد. فونت‌های بدون حروف عربی/فارسی از وزیرمتن برای بخش فارسی استفاده می‌کنند. همهٔ فونت‌ها الزاماً حروف فارسی ندارند و بعضی نمایش‌دهنده‌های موبایل ممکن است فونت جاسازی‌شده را نادیده بگیرند.

دریافت فونت با Google Fonts CSS API و بدون کلید انجام می‌شود؛ متن سند ارسال نمی‌شود. فهرست همراه برنامه از metadata عمومی گوگل تهیه شده و گزینهٔ به‌روزرسانی دارد؛ در دسترس نبودن آن به فهرست آفلاین آسیب نمی‌زند. API رسمی Developer برای فهرست پویا به کلید نیاز دارد و در این نسخه استفاده نشده است. تبدیل سند پس از دریافت فونت آفلاین می‌ماند؛ دادهٔ فونت با پاک‌کردن دادهٔ اپ یا حذف برنامه پاک می‌شود.

در ۰.۲ فاصله و نشانه‌ها از متن فارسی جدا می‌شدند و کاربر با تصویر Word اندروید خرابی آن را تأیید کرد. در ۰.۲.۱ جهت برای عبارت کامل، پیش از تقسیم پررنگ/مورب/لینک، تعیین می‌شود. فاصله و نشانهٔ فارسی در زمینهٔ RTL می‌مانند و عبارت انگلیسی یا شماره در زمینهٔ LTR قرار می‌گیرد. در مرزهای مبهمِ عبارت عددی یا نشانه‌دار، علامت استاندارد نامرئی LRM فقط به خروجی DOCX اضافه می‌شود؛ متن Markdown پیش‌نویس تغییر نمی‌کند. هنگام کپی یا جست‌وجوی متن در Word ممکن است این کاراکتر نامرئی همراه متن باشد. روش آزمایشی B که در گوشی جمله‌ها را جابه‌جا کرد کنار گذاشته شده است. تأیید عمومی نسخهٔ تازه در Microsoft Word اندروید هنوز با تست گوشی انجام می‌شود.

نسخهٔ اولیهٔ اندروید برای تبدیل Markdown به Word قابل ویرایش، با توجه به متن فارسی، انگلیسی و پرانتزها. تبدیل و ذخیرهٔ پیش‌نویس روی دستگاه انجام می‌شود. برای ساخت فایل، سرور، حساب کاربری یا نصب Word لازم نیست. APK تحویلی برای اندروید ۷ به بالا و فقط معماری ARM64 ساخته می‌شود. طبق درخواست کاربر، از ۰.۲.۴ خروجی اندروید x86/x86_64 یا ARM32 ساخته نمی‌شود؛ پیش‌فرض‌های Gradle و فرمان‌های npm نیز ARM64 هستند.

## استفاده روی گوشی

1. APK آزمایشی را نصب کن و برنامه را باز کن.
2. متن را بنویس یا از «باز کردن فایل»، فایل Markdown یا متنی انتخاب کن.
3. از «پیش‌نمایش» ساختار متن را بررسی کن.
4. از تنظیمات پایین صفحه، جهت و اندازهٔ قلم را انتخاب کن.
5. «ذخیرهٔ فایل Word» را بزن و محل ذخیره را در انتخابگر اندروید مشخص کن.

برای بررسی از «متن‌های نمونه»، «آزمایش پرانتزها» یا «متن ترکیبی و نشانه‌ها» را انتخاب کن. جهت «خودکار» برای تشخیص مستقل پاراگراف فارسی و انگلیسی مناسب است. «حالت مقایسه: فقط راست‌چین» خروجی تشخیصی بدون تنظیم جهتِ عبارت‌ها می‌سازد؛ برای استفادهٔ عادی خاموش بماند. ترتیب منطقی حروف و کاراکترهای پرانتز هنگام تبدیل تغییر نمی‌کنند.

پیش‌نمایش داخل اپ، نمایش Markdown در WebView است و صفحه‌بندی Word را شبیه‌سازی نمی‌کند. تصاویر کاربر مشکل را در Word اندروید بازتولید کرده‌اند. فایل‌های آزمایشی جدید با خود تبدیل‌کننده ساخته و در LibreOffice بررسی تصویری شده‌اند؛ این بررسی جای تست نسخهٔ تازه در Word اندروید را نمی‌گیرد.

## امکانات و محدودیت‌ها

- رابط فارسی و ویرایشگر مناسب موبایل؛ ذخیرهٔ خودکار یک پیش‌نویس روی دستگاه.
- تیتر، پررنگ، مورب، خط‌خورده، نقل‌قول، لینک، فهرست چندسطحی، جدول و کد.
- جهت RTL، LTR یا تشخیص مستقل جهت هر پاراگراف؛ جهت عبارت‌ها با ویژگی‌های استاندارد Word و اطلاعات Unicode.
- خروجی A4 با فونت و اندازهٔ قابل تنظیم. کد همیشه LTR صادر می‌شود.
- انتخابگر استاندارد اندروید برای واردکردن و ذخیرهٔ فایل، بدون دسترسی گسترده به حافظه.

این نسخه کلون کامل md2word نیست. PDF، تصویر، تبدیل فرمول LaTeX و Mermaid ندارد. تصویر با متن جایگزین صادر می‌شود؛ فرمول به صورت متن باقی می‌ماند. فونت‌های دریافت‌شده در DOCX جاسازی می‌شوند؛ فونت‌های سیستم جاسازی نمی‌شوند و نمایش‌دهنده ممکن است فونت جایگزین انتخاب کند. پیش‌نویس حداکثر ۵۰۰ هزار نویسه است. بازگشت به متن قبلی فقط در همان اجرای برنامه ممکن است. دادهٔ محلی با حذف دادهٔ برنامه پاک می‌شود. پلتفرم‌های دیگر هنوز ساخته و آزمایش نشده‌اند.

## توسعه

React + TypeScript + Vite + Tailwind 4 + shadcn/ui، هستهٔ تبدیل با `docx`، `remark` و `bidi-js`، و پوستهٔ Tauri 2 با پلاگین‌های رسمی dialog و fs.

نیازمندی‌ها: Node.js 22.12+ یا 24، Rust stable، JDK 21، Android SDK Platform 36، Build Tools 36 و NDK 28.2.13676358. متغیرهای `JAVA_HOME`، `ANDROID_HOME` و `NDK_HOME` را برای محل نصب خود تنظیم کن. پروژهٔ Android Studio داخل `src-tauri/gen/android` است. قفل وابستگی‌های npm و Cargo همراه پروژه است.

```sh
npm ci
rustup target add aarch64-linux-android
npm run build
npm test
npx playwright install chromium
npm run test:ui
npm run android:apk
```

برای توسعه با گوشی یا شبیه‌ساز:

```sh
npm run tauri -- android dev
```

فرمان `npm run dev` نسخهٔ مرورگری را برای آزمون رابط اجرا می‌کند. مسیر انتخابگر فایل مرورگر با مسیر اندروید متفاوت است.

برای release، `npm run android:apk` را اجرا کن؛ این فرمان فقط ARM64 می‌سازد. `npm run android:preview` هم پیش‌نمایش debug را فقط برای ARM64 می‌سازد. پیش‌فرض‌های RustPlugin و فیلتر ABI پروژهٔ اندروید نیز روی ARM64 قرار دارند. تغییرهای پروژهٔ تولیدشدهٔ Android را هنگام اجرای دوبارهٔ `tauri android init` حفظ کن.

APK release قبل از نصب نیاز به امضا دارد؛ کلید خصوصی را بیرون از مخزن نگه دار و از راهنمای امضای Android در مستندات Tauri استفاده کن. بستهٔ تحویلی ۰.۲.۴ build غیرdebug از پروفایل release است که برای سازگاری با نسخه‌های قبلی با همان کلید پیش‌نمایش موجود امضا می‌شود؛ انتشار فروشگاهی نیست. برای انتشار فروشگاهی از کلید توزیع اختصاصی استفاده شود. کتابخانهٔ بومی فشرده می‌شود و هنگام نصب استخراج می‌شود؛ هم‌ترازی ELF برای صفحه‌های ۱۶کیلوبایتی هم بررسی می‌شود. بررسی APK نهایی با `python scripts/verify-android-apk.py PATH_TO_APK --compare-with PREVIOUS_APK` انجام می‌شود. پیام عمومی «App not installed» در عکس قبلی به‌تنهایی علت خطا را روشن نمی‌کرد؛ تأیید نصب نسخهٔ جدید باید روی گوشی انجام شود.

## اعتبارسنجی

آزمون‌های DOCX فایل XML داخل سند را بررسی می‌کنند: حفظ متن، پرانتز تو‌در‌تو، بخش انگلیسی، جهت کد، جدول، فهرست و حالت مقایسه. آزمون‌های Playwright در اندازهٔ Pixel 7، ویرایش، واردکردن، پیش‌نمایش، ذخیرهٔ پیش‌نویس، بازگشت به متن قبلی و دانلود فایل واقعی را پوشش می‌دهند.

۷۷۷ آزمون واحد و ۴ آزمون مرورگر پاس شده‌اند. خروجی واقعی S11 و P01/P02 در LibreOffice با مرجع مستقل تطبیق دارد و ۱۴ علامت فونت جایگزین دیده می‌شوند؛ نتیجهٔ نسخهٔ جدید در Word اندروید هنوز باید بررسی شود. S09 در عکس Word گوشی کاربر درست بود و مسیرش حفظ شده است؛ اختلاف قدیمی LibreOffice در این مورد باقی است. در موارد تودرتوی RTL داخل پاراگراف LTR، RLE/PDF استاندارد فقط به خروجی DOCX اضافه می‌شوند و در کپی/جست‌وجو ممکن است همراه متن باشند. شرح تصمیم در `docs/adr/0004-nested-rtl-in-ltr.md` است.

برای ساخت آزمون کوتاه دوصفحه‌ای، `node scripts/export-fix-check.mjs` را اجرا کن. برای آزمون سخت با دو صفحه مرجع مستقل، `node scripts/export-hard-stress.mjs ../artifacts/0.2.3/` را اجرا کن. خروجی هر دو در `artifacts/0.2.3` است. بازسازی فونت جایگزین با `python scripts/build-delimiter-font.py` و fontTools انجام می‌شود. شرح کتابخانهٔ آماده، دامنهٔ آزمون و محدودیت‌ها در `docs/rtl-hard-stress.md` است. تنظیمات جهت با APIهای آمادهٔ `rightToLeft` و `bidirectional` کتابخانهٔ docx اعمال می‌شوند؛ فرمان داخلی RtlRun وابسته به اجرای خود Word است و معادل‌بودن دقیق آن با ذخیرهٔ قبل/بعد در Word تأیید نشده است. برای نمونه‌های ساده‌تر، `node scripts/export-verification.mjs` قابل استفاده است.
