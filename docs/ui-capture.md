# عکس‌گرفتن از رابط با یک فراخوانی

برای بررسی ظاهر کامپوننت‌های ParsiWord از این ابزار استفاده کن. عکس از
پیکسل‌های واقعی Chromium گرفته می‌شود، بنابراین فونت، فرمول، نمودار،
اسکرول و موقعیت `sticky` همان چیزی هستند که مرورگر نشان می‌دهد.
این مسیر از Playwright یا تبدیل DOM به تصویر استفاده نمی‌کند.

## اجرای سریع

از ریشهٔ پروژه، پس از `npm ci`، با Node.js 22.12+ یا 24 و یک Chrome/Chromium
نصب‌شده اجرا کن:

```sh
npm run ui:capture -- --width 1100 --height 800 --output artifacts/ui-desktop.png
```

ابزار در صورت نیاز Vite را روی `http://127.0.0.1:1420` اجرا می‌کند؛ اگر
همان سرور توسعه از قبل فعال باشد، از آن استفاده می‌کند. مرورگر و پروفایل
موقت متعلق به ابزار پس از پایان بسته/پاک می‌شوند؛ سرور موجود بسته نمی‌شود.
اجراهای مستقل را پشت سر هم انجام بده تا برای پورت Vite رقابت نکنند.

در این محیط Chromium از کش موجود پیدا می‌شود؛ صرفاً فایل اجرایی آن استفاده
می‌شود و Playwright اجرا نمی‌شود. در محیط دیگر مسیر مرورگر را صریح بده:

```sh
CHROME_BIN=/usr/bin/chromium npm run ui:capture -- --output artifacts/ui.png
# یا
npm run ui:capture -- --chrome /path/to/chrome --output artifacts/ui.png
```

## متن مشخص، موبایل و اسکرول

فایل Markdown اختیاری با UTF-8 خوانده می‌شود. بدون آن، پیش‌نویس پروفایل
موقت/متن شروع اپ نمایش داده می‌شود؛ پیش‌نویس مرورگر شخصی تغییر نمی‌کند.

```sh
# دسکتاپ
npm run ui:capture -- --width 1100 --height 800 --markdown /tmp/demo.md --output artifacts/desktop.png

# ویرایش موبایل و پیش‌نمایش همان متن
npm run ui:capture -- --width 393 --height 851 --view edit --markdown /tmp/demo.md --output artifacts/mobile-edit.png
npm run ui:capture -- --width 393 --height 851 --view preview --markdown /tmp/demo.md --output artifacts/mobile-preview.png

# پیش‌نمایش موبایل باریک
npm run ui:capture -- --width 320 --height 780 --view preview --markdown /tmp/demo.md --output artifacts/mobile-small.png

# متن بلند، بعد از اسکرول صفحه؛ برای دیدن toolbar چسبان
npm run ui:capture -- --width 393 --height 851 --view edit --markdown /tmp/long.md --scroll 1400 --output artifacts/mobile-scroll.png
```

اندازه‌ها بر حسب CSS pixel هستند؛ کوچک‌ترین اندازهٔ پذیرفته‌شده ۳۲۰×۳۲۰
است. خروجی PNG فقط viewport است تا سندهای بلند تصویر چندده‌هزارپیکسلی
نسازند. `--view` در موبایل تا عرض ۸۹۹px پنل فعال را انتخاب می‌کند؛ بدون آن
حالت آغازین ویرایش است. در دسکتاپ هر دو پنل دیده می‌شوند و این گزینه
چیدمان را تغییر نمی‌دهد. `--scroll` مربوط به **صفحه** است؛ در موبایل هر
دو حالت با صفحه اسکرول می‌شوند و در دسکتاپ پیش‌نمایش اسکرول داخلی دارد.
اسکرول ویرایش و پیش‌نمایش بر اساس بلوک‌های متن هماهنگ می‌شود. این عکس‌ها
شبیه‌سازی viewport مرورگرند، تأیید اجرای بومی Android/iOS محسوب نمی‌شوند.

در اندروید، Activity فاصلهٔ نوارهای سیستم و بریدگی را به والد WebView
می‌دهد و همان insets را پیش از رسیدن به CSS مصرف می‌کند؛ insets صفحه‌کلید
همچنان منتقل می‌شوند. بررسی viewport معمولی این مسیر بومی را اجرا نمی‌کند.
برای بررسی اشکال فاصلهٔ دوبارهٔ نوار چسبان، نتیجهٔ مرورگر را از نتیجهٔ
نصب و اجرای APK جدا ثبت کن؛ فقط تغییر `--width` و `--height` آزمون ناحیهٔ
امن یا بازشدن صفحه‌کلید گوشی نیست.

خروجی فرمان یک JSON کوتاه با مسیر عکس، ابعاد، `overflow` افقی، حالت واقعی
نمایش (`edit`، `preview` یا `both`)، دیده‌شدن و ارتفاع دو پنل، موقعیت نوار
قالب‌بندی Markdown (`toolbarTop`)، نوار ویرایش پیش‌نمایش (`richToolbarTop`)
و انتخابگر موبایل (`viewSwitchTop`) و تعداد badgeهای حذف‌شده است.
`richEditorEditable` نیز فعال‌بودن ویرایش مستقیم پیش‌نمایش را گزارش می‌کند.
اندازه‌های پنل پنهان و موقعیت toolbar پنهان
`null` هستند؛ صفر به معنی قد واقعی متن نیست.
برای بررسی نتیجه، PNG را واقعاً باز کن. در متن بلند انتظار داریم:

- `overflow` برابر `false` باشد.
- وقتی ادیتور دیده می‌شود، `editorHeight` و `editorScrollHeight` برابر باشند؛
  ادیتور اسکرول داخلی ندارد.
- در موبایل فقط پنل انتخابی دیده شود و انتخابگر هنگام اسکرول در دید بماند؛
  در حالت ویرایش، نوار قالب‌بندی زیر آن بچسبد.
- نوار ابزار پیش‌نمایش موبایل دو ردیف و اسکرول افقی داخلی داشته باشد؛
  نمودارهای عریض هم داخل محفظهٔ خودشان اسکرول شوند. راهنمای نمودار فقط وقتی
  محتوا از محفظه عریض‌تر است دیده شود؛ صفحه نباید overflow افقی پیدا کند.
- `badges` برابر صفر باشد؛ «زنده» و «روی دستگاه تو» حذف شده‌اند.
- ذخیره و تنظیمات بالای سند باشند؛ جهت زیر تیتر اصلی قرار بگیرد.

در بازبینی ۰.۴.۶، نمونهٔ اسکرول‌شدهٔ موبایل انتخابگر را در y=0 و نوار
Markdown را در y=60 نگه داشت؛ ارتفاع ادیتور و محتوایش هر دو ۳۰٬۱۵۰px بود.
عکس‌های پیش‌نمایش، منبع، عرض باریک و دسکتاپ همگی بدون سرریز افقی و بدون
نشان‌های حذف‌شده بودند. این مختصات مربوط به viewport مرورگر است.

## تابع داخل اپ

کامپوننت اپ در حالت توسعه این API را نصب می‌کند:

```ts
await window.parsiwordDev.screenshot({
  markdown: '# عنوان\n\nمتن فارسی با React (version **19**).',
  view: 'preview',
  scrollY: 1400,
}); // Promise<string>: مسیر PNG ذخیره‌شده
```

همهٔ گزینه‌ها اختیاری‌اند. تابع ابتدا متن React را تنظیم می‌کند، منتظر
پیش‌نمایش با تأخیر ۲۰۰ میلی‌ثانیه، فونت‌ها و نمودارها می‌ماند، حالت موبایل
درخواستی را انتخاب می‌کند و پس از تثبیت چیدمان، `scrollY` را اعمال می‌کند.
پس از تغییر حالت نیز منتظر آماده‌شدن پیش‌نمایش می‌ماند و دو فریم مرورگر
پیش از درخواست عکس صبر می‌کند. انتظار آماده‌شدن پیش‌نمایش حداکثر
۳۰ ثانیه است. مسیر ذخیره، ابعاد و اتصال CDP را runner تعیین می‌کند؛ این
تابع در یک تب معمولی که bridge ندارد، پیام اجرای `npm run ui:capture` می‌دهد.

پیاده‌سازی: [src/dev-capture.ts](../src/dev-capture.ts)، بارگذاری توسعه‌ای در
[src/App.tsx](../src/App.tsx) و runner در
[scripts/capture-ui.mjs](../scripts/capture-ui.mjs).
این API فقط با `import.meta.env.DEV` بارگذاری می‌شود؛ داخل خروجی production
یا APK قابلیت عکس‌گرفتن و اتصال دیباگ اضافه نمی‌شود. هیچ کتابخانهٔ اجرایی
جدید برای این قابلیت به اپ اضافه نشده است.

این روش برای بازبینی ظاهر است. تست‌های موجود تبدیل Word، جهت متن، فونت و
رفتار اپ را حذف نکن؛ وقتی تغییر رفتار نیاز به تست دارد، تست مرتبط را جدا
اجرا کن. نیازی به اجرای مجدد کل مجموعه برای هر جابه‌جایی ظاهری نیست.

## سنجش تایپ

عکس‌گرفتن زمان پاسخ تایپ را اندازه نمی‌گیرد. برای مقایسهٔ کارایی، هر دو
نسخه را با `npm run build` بساز و با Vite preview روی پورت‌های جدا اجرا
کن؛ سپس در ترمینال دیگر پروتکل ثابت را برای هر پورت اجرا کن:

```sh
node scripts/profile-rich-input.mjs --label production-after --cpu 4 --repeat 1 --url http://127.0.0.1:1421 --output artifacts/rich-input-production-after.json
```

ابزار از سند نمونه همراه عنوان و پاراگراف ورودی استفاده می‌کند؛ نسخهٔ
پیش‌فرض ۲۸٬۱۴۷ نویسه، ۳۹۳×۸۵۱px و ۳۲ کلید با فاصلهٔ ۳۵ms دارد. زمان از
`beforeinput` تا اولین `requestAnimationFrame` اندازه‌گیری می‌شود. این
زمان‌بندی مرورگر است، نه پایان رسم GPU یا تأخیر دستگاه اندرویدی. مشخصات
محیط، هش نمونه و نتیجهٔ production پیش و پس از اصلاح در
[گزارش ۰.۴.۶](releases/0.4.6-performance.json) هستند؛ هر اجرای مستقل حفظ
شده و میانگین چند اجرا به‌جای توزیع زمان‌ها گزارش نشده است. هنگام سنجش،
ویرایش فایل‌ها و HMR را متوقف کن تا reload با زمان تایپ مخلوط نشود.
