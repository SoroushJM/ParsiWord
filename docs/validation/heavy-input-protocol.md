# پروتکل ورودی سنگین

ابزار `scripts/profile-rich-input.mjs` همان سناریوی قبلی `typing` را نگه می‌دارد و چهار سناریوی ثابت اضافه می‌کند. این سنجش Chromium روی Windows با viewport برابر ۳۹۳×۸۵۱ و کندسازی CPU برابر ۴ است؛ زمان‌بندی دستگاه واقعی یا SLO عمومی محصول نیست. هر حالت ابتدا یک بار اجرا می‌شود؛ تکرار فقط برای نتیجهٔ پرنوسان یا پس‌رفت معنادار است.

| سناریو | ورودی ثابت | بررسی مستقل |
| --- | --- | --- |
| `long-block`، منبع و rich | یک پاراگراف فارسی/لاتین حدود ۲۰۰ هزار نویسه؛ درج ۳۲ نویسه در میانه | منبع کامل و متن کامل همان پاراگراف |
| `many-blocks`، منبع و rich | ۲۰۰۰ پاراگراف با نمونهٔ کوچک bold/reference/code/math؛ ویرایش پاراگراف ۱۰۰۰ | منبع کامل و متن پاراگراف هدف |
| `paste`، منبع و rich | پاراگراف ۱۸۰ هزار نویسه‌ای با sentinel پایانی؛ paste بومی ۱۰۰ هزار نویسه از clipboard | منبع نهایی ۲۸۰ هزار نویسه و متن پاراگراف هدف |
| `view-switch` | ۲۰ جابه‌جایی بین تب‌های موجود وب در همان ورودی ۲۰۰۰ پاراگرافی | منبع، پاراگراف و نمای فعال پس از هر جابه‌جایی |

متن و نقطهٔ درج از generator ثابت می‌آیند؛ hash ورودی، payload و خروجی مورد انتظار در هر گزارش ثبت می‌شود. hash منبع `long-block` برابر `9d672f3708cfbc1b93e462de01f161cef788e093d32e710eb04e951180c34ac9`، منبع `many-blocks/view-switch` برابر `3564977baea435f02042156f15500bcfa94ace59d51065ae813ed694b40ddd9a` و منبع `paste` برابر `a43573d808e5cf8c26f8705b449b0459501bd934c5ad5b08ab53ed328fa48900` است.

CPU از پیش از navigation کند می‌شود. زمان navigation و ready جدا ثبت می‌شوند؛ شکست initialization با زمان سپری‌شده در JSON می‌ماند. latency از رویداد `beforeinput`، `paste` یا click تا اولین callback در `requestAnimationFrame` است؛ این عدد زمان تکمیل layout/paint یا نمایش نهایی نیست. شمارش long task از نصب observer تا خواندن نتیجه ادامه دارد و آماده‌سازی clipboard/profiler را هم شامل می‌شود؛ بنابراین جمع آن الزاماً زیر `elapsedMs` محدود نمی‌شود. شمارنده‌های CDP، رخدادهای layout/style/paint و CPU profile در بازهٔ جداگانهٔ ثبت‌شده پیرامون عملیات جمع می‌شوند. نمونه‌های CPU شمارش فراخوانی parse/serialize نیستند؛ minification نسبت‌دادن نام‌ها را محدود می‌کند.

مقایسهٔ مبنا روی build تولیدی منجمد `f38dde8` در پورت ۱۴۲۱ انجام شد. هفت گزارش و profile در `artifacts/heavy-before-*` و نسخهٔ گردآوری‌شدهٔ گزارش‌ها در `docs/validation/heavy-baseline.json` نگه‌داری می‌شوند. در هر سه حالت rich مبنا، متن پاراگراف و ورودی درست بود ولی serializer فقط newline پایانی منبع را حذف کرد؛ این شکست دقیق منبع ثبت شده و پنهان نشده است. نسخهٔ جدید باید قرارداد حفظ منبع را رعایت کند.

پیش از بهینه‌سازی، آستانه‌های بازبینی پذیرفته شدند: افزایش p95 که هم بیش از ۲۰٪ و هم بیش از ۱۶ms باشد؛ افزایش مجموع long task که هم بیش از ۲۵٪ و هم بیش از ۵۰ms باشد. ناسازگاری متن یا تعداد رویداد در نسخهٔ جدید شکست correctness است. p95 بالاتر از ۱۰۰ms و task بالاتر از ۵۰ms علامت بررسی‌اند، نه تضمین یکسان روی سخت‌افزارهای مختلف. اجرای AFTER باید با build نهایی منجمد، همین ابزار/ورودی/viewport/CPU و بدون مرورگر سنجش رقیب انجام شود.

نمونهٔ اجرا: `node scripts/profile-rich-input.mjs --scenario long-block --editor source --cpu 4 --width 393 --height 851 --url http://127.0.0.1:1421 --label heavy-before-long-block-source --output artifacts/heavy-before-long-block-source.json --profile artifacts/heavy-before-long-block-source.cpuprofile`.

## مقایسهٔ نهاییِ محدود

طبق درخواست نهایی کاربر، پس از freeze و سبزشدن ۱۰۳۳ آزمون واحد، guard معماری و build، فقط سه اجرای زیر انجام شد. build تولیدی نهایی با bundle برابر `main-B72Ki8-z.js` در `artifacts/architecture-after-frozen` ثابت شد؛ گزارش کامل و hash bundle در `performance-comparison.json` همین پوشهٔ اسناد است. fixture، ورودی، مرورگر، viewport، CPU و زمان‌های settle با مبنا تطبیق داده شدند. هر ردیف فقط یک اجرای مشاهده‌شده است، نه برآورد آماری چند اجرا.

| حالت | p95 پیش از تغییر → نهایی | مجموع long task پیش از تغییر → نهایی | صحت ثبت‌شده |
| --- | --- | --- | --- |
| منبع عادی، ۲۸٬۱۴۷ نویسه | ۶۳ → ۷۰ms | ۵۵۶ → ۸۲۶ms؛ ۴۸٫۶٪ افزایش | ۳۲ رویداد، منبع و overlay دقیق، صفر frame رنگی stale |
| rich عادی، همان ورودی | ۶۳ → ۷۷ms | ۵۸۶ → ۹۶۱ms؛ ۶۴٪ افزایش | ۳۲ رویداد؛ ابزار قدیمی schema-1 برای این ردیف assertion کامل منبع ندارد |
| rich، همان پاراگراف ۲۰۰٬۰۴۰ نویسه‌ای | ۱۵۳۲ → ۱۳۵۸ms | ۲۷٬۱۹۲ → ۲۰٬۹۱۳ms؛ ۲۳٫۱٪ کاهش | ۳۲ رویداد، کل منبع و کل پاراگراف دقیق؛ newline پایانی هم حفظ شد |

افزایش p95 در دو حالت عادی به‌ترتیب ۷ و ۱۴ms بود؛ هیچ‌کدام هر دو شرط آستانهٔ p95 را رد نکردند. افزایش مجموع long task در هر دو حالت عادی از آستانهٔ بازبینی گذشت و هزینهٔ باقی‌ماندهٔ اندازه‌گیری‌شده است؛ به‌عنوان بهبود گزارش نمی‌شود. پاراگراف بلند در این نمونه کمتر زمان برد ولی همچنان کند است. طبق دستور بستن این ویژگی، حلقهٔ بهینه‌سازی یا تکرار اختیاری انجام نشد. شش حالت سنگین AFTER دیگر اجرا نشده‌اند و عملکرد نهایی‌شان اندازه‌گیری نشده است.

در rich، spelling جدیدِ نویسهٔ درج‌شده ممکن است escape یا entity فاصله باشد؛ این با حذف ورودی یا تغییر بخش نامرتبط یکسان نیست. آزمون‌های منبع و مرورگر جدا این تمایز را بررسی می‌کنند. برای ردیف rich عادی از تعداد رویدادها برابری کامل متن نتیجه نمی‌گیریم؛ شاهد مستقیمِ برابری کاملِ این سنجش، ردیف پاراگراف بلند است. CPU profile و JSON خام هر سه اجرا در `artifacts/*after-final*` و `artifacts/heavy-after-long-block-preview.*` حفظ شدند. preview اختصاصی پورت ۱۴۲۲ پس از سه اجرا بسته شد؛ سرور مبنای پورت ۱۴۲۱ دست‌نخورده ماند.

**تصمیم review سرپرست:** هزینهٔ long task عادی بالاتر است و بهبود عمومی کارایی پذیرفته نشده است. با توجه به عبور بررسی‌های صحت، افزایش ۷/۱۴ms در p95 عادی و دستور صریح کاربر برای پایان‌دادن سناریوهای سنگین، این هزینه به‌عنوان محدودیت اندازه‌گیری‌شده و کار اختیاری آینده پذیرفته شد؛ تست یا دور بهینه‌سازی دیگری شرط بستن این دامنه نیست. سرپرست پس از خواندن گزارش، سرور مبنای ۱۴۲۱ را نیز بست.
