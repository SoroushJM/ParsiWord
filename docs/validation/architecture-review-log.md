# سابقهٔ review معماری — ۲۰۲۶-۱۰-۲۳

این گزارش ترتیب یافته‌ها و اصلاح‌های اولیه را نگه می‌دارد؛ عبارت‌های «باز» و «در حال اصلاح» در آن تاریخی‌اند. وضعیت جاری را از [فایل پیشرفت](../implementation-progress.md) بخوان.

## review سرپرست تا این نقطه

- roadmap اصلاح‌شده خوانده و دامنه/ترتیب با تصمیم‌های کاربر تطبیق داده شد.
- API تم و مالکیت snapshot/limits/mode تأیید شد؛ پذیرش نهایی اجرای آن‌ها هنوز باز است.
- کد اولیهٔ `display-theme.ts` خوانده شد؛ یادآوری شد تم نمایش نباید SVG کش‌شدهٔ Mermaid مشترک با export را تغییر دهد.
- سرپرست با parse واقعی unified ثابت کرد تعریف مرجع می‌تواند داخل blockquote باشد؛ جمع‌آوری فقط `root.children` ناقص است. عامل core گزارش داده traversal بازگشتی با first-definition-wins را اصلاح کرده؛ fixture و review نهایی باقی است.
- پارامتر context اختیاری عمومی `createWord` می‌توانست متن و AST متعلق به نسخه‌های متفاوت را بپذیرد؛ عامل core آن را به helper خصوصی منتقل کرده و API قبلی را نگه داشته است؛ diff نهایی باید بررسی شود.
- در VS Code رنگ لینک/مکان‌نما/focus نباید به رنگ پس‌زمینهٔ دکمه متکی باشد. از عامل تم خواسته شد این‌ها را به توکن‌های اختصاصی VS Code نگاشت و در light/dark/high-contrast بررسی کند.
- کد اولیهٔ `document-session`، limits، و source mapping در دست review است. سه تست خالص تم از سوی عامل پاس شده‌اند؛ پذیرش بصری و رفتار کامل هنوز باز است.
- یافته‌های W3 با اجرای واقعی helper اولیه: حذف اولین `a` از `&#97;a` اشتباهاً entity را نگه می‌داشت؛ حذف فاصله از `a * b*` قالب italic ناخواسته می‌ساخت؛ حذف فاصله از `a & amp; b` متن را به entity تبدیل می‌کرد؛ یک تغییر در literal autolink به `RICH_SOURCE_MAP_MISMATCH` می‌رسید. عامل core باید از StepMap واقعی transaction برای provenance و از بررسی معنایی/ترمیم delimiter در بلوک متاثر استفاده کند. این موارد هنوز در حال اصلاح‌اند و با عبور چند تست ساده بسته نمی‌شوند.
- یافته‌های W4/W6 برای عامل میزبان: validator اولیهٔ edit سند بیش‌ازحد را حتی هنگام کوچک‌شدن رد می‌کرد؛ snapshot ورودی حین composition می‌تواند tail هنوز ارسال‌نشده را overwrite کند؛ source recovery سند بزرگ در موبایل وب باید واقعاً دیده شود. fixture و رفع این موارد خواسته شده است.
- W5: `App.convert` هنوز ابتدا از رشته برای انتخاب فونت parse می‌کند و سپس خروجی context دیگری می‌سازد. core و میزبان باید روی یک عملیات prepared با snapshot ثابت هماهنگ شوند؛ API عمومی نباید source و context ناسازگار مستقل بپذیرد.
- آخرین review همگام‌سازی: وقتی IME پس از `drain()` به متن اولیه برمی‌گردد، ممکن است `pending=false` شود ولی waiter بدون `receive()` تا timeout بماند. settle شدن در cancellation و نتیجهٔ ناموفق `document.save()` برای اصلاح به عامل میزبان فرستاده شد.
- عامل میزبان گزارش داده cancellation waiter و Save ناموفق را اصلاح کرده و race تازهٔ dispose/init را نیز با enqueue فوری و انتظار صف مشترک provider جدید بسته است؛ تست‌های lifecycle بومی در جریان‌اند. تست ترتیب compositionend پیش از آخرین input نیز خواسته شد.
- milestone core: APIهای context-only برای Word/PDF، collector مشترک definitions، ادغام ledger در EditablePreview و guard نهایی طول پیاده شده‌اند؛ هنوز تحویل کامل نیست. سرپرست مستقل پنج فایل unit را اجرا کرد: ۳۸ پاس و ۱ شکست (`rich-source.test.ts:58`، plain literal autolink → `RICH_SOURCE_MAP_MISMATCH`). عامل core در حال رفع این مورد است؛ گزارش قبلی ۲۵ پاس مربوط به نسخه/fixture قبلی بود.
- دو یافتهٔ باز W3 دیگر: زنجیرهٔ `parent` snapshotها تمام متن/مدل هر کلید را بدون حد نگه می‌داشت؛ عامل core در حال اتصال نگهداری provenance به عمر واقعی history است. fallback تغییر ساختاری در list/table نباید sibling نامرتبط را normalize کند؛ fixture کوچک‌ترین زیرساختار لازم خواسته شد.
- هنوز هیچ بستهٔ کد به‌عنوان تحویل نهایی پذیرفته نشده است.

## بازبینی مستقل پس از آغاز موارد سنگین

- سرپرست یک probe محلی با transaction واقعی PM برای درج/حذف در موقعیت‌های مختلف اجرا کرد (`artifacts/review-rich-probe.mjs` و نتیجهٔ JSON هم‌نام). مقایسهٔ سخت مدل شامل تفاوت‌های طبیعی trim فاصله و موقعیت مصنوعی میان surrogate نیز بود؛ تعداد mismatchهای خام، تعداد bug محصول نیست.
- یافته‌های قطعی: درج `X` در `a * b*` می‌توانست italic ایجاد کند؛ حذف/درج کنار `__bold__` شرط flanking را می‌شکست و bold را از منبع می‌انداخت؛ حذف نخستین حرف می‌توانست marker فهرست را فعال کند؛ ویرایش label لینک خودکار، href را در منبع عوض می‌کرد در حالی که مدل rich مقصد قدیم را داشت؛ fallback یک entity چندنویسه‌ایِ نامرتبط مثل `&NotEqualTilde;` را normalize می‌کرد. عامل core برای این‌ها تست واقعی و اصلاح موضعی اضافه کرد؛ اجرای مستقل پس از اصلاح هنوز لازم است.
- W8 از نظر facadeهای سازگار، guard مبتنی بر AST، وابستگی‌های Node-safe، خطاها و فیلتر CI خوانده و موقتاً پذیرفته شد. toastهای مستقیم `String(error)` در webview برای استفاده از پیام ترجمه‌شده به عامل میزبان برگشتند.
- مسیر source → preview در کمتر از ۲۰۰ms فقط layout را عوض می‌کرد و مقدار preview را فوراً flush نمی‌کرد؛ خطر ویرایش rich قدیمی و overwrite متن جدید به عامل میزبان داده شد و او با خواندن کد تأیید کرد. regression مرورگر و flush دوطرفه هنگام switch/focus لازم است.
- تست‌های تازهٔ Word/PDF با فایل واقعی، نرم‌خط، hard break، reference، snapshot و رنگ اپراتورهای خروجی را می‌سنجند؛ تستی که همان PNG آزمایشی را در هر دو تم inject می‌کند فقط استقلال adapter را ثابت می‌کند. برای M13، تولید واقعی KaTeX/Mermaid در دو context تازهٔ مرورگر و مقایسهٔ خروجی خواسته شد.
- کاربر خواستهٔ پوستهٔ بومی VS Code را افزود؛ goal/roadmap/progress به‌روزرسانی و اجرا به عامل تم واگذار شد. وب تغییر چیدمان ندارد؛ فونت سند مستقل می‌ماند.

## بستن یافته‌ها

یافته‌های مشخص بالا با fixture و review اصلاح شدند: StepMap occurrenceها، مرزهای syntax و entity چندنویسه‌ای، hard break آغاز/پایان، حفظ sibling در split list، cache دومین ویرایش code و raw widget با تعداد بلوک متغیر؛ history از نگه‌داشتن زنجیرهٔ نامحدود متن جدا شد. race سوییچ با timer نمایشی متوقف‌شده تست دارد؛ Save/IME/dispose در VS Code واقعی پاس است. M13 با renderer واقعی در دو context تازه بسته شد.

سرپرست در تصاویر نهایی یک اشکال HC Light دیگر دید: token preformat سفید روی editor سفید. CSS محدود اصلاح و شاهد native کوچک قبل/بعد با کنتراست ۱→۱۴٫۵۵ ثبت شد. اجرای integration همچنین مهاجرت اشتباه `alignmentOnly:true` قدیمی را آشکار کرد؛ normalizeSettings اکنون مانند مبنا آن حالت مقایسهٔ بازنشسته را خاموش می‌کند. سه شکست دیگر انتظار تست بودند؛ source پیرامون درج همچنان دقیق و اعلان واقعی قابل‌دیدن الزام شده‌اند. نتایج کامل و محدودیت‌های پذیرفته‌شده در [گزارش تحویل](implementation-acceptance.md) هستند؛ هیچ یافتهٔ الزامیِ شناخته‌شده‌ای باز نماند. هزینهٔ long task عادی و سناریوهای AFTER اضافه با دستور کاهش دامنه به backlog منتقل شدند.
