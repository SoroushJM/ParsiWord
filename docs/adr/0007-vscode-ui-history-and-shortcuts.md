# رابط پارسی‌ورد، تاریخچهٔ سند و میان‌برهای VS Code

بخش چیدمان دو گروه در نسخهٔ ۰.۱.۱ با [تصمیم ۰۰۰۸](0008-single-tab-comparison-and-images.md) جایگزین شده است: مقایسه در یک تب مشترک باز می‌شود. الزامات تاریخچهٔ بومی، پوستهٔ ثبت‌شده در Git و دامنهٔ میان‌برهای این تصمیم همچنان برقرارند.

مقایسهٔ Git باید منبع راست‌به‌چپ و پیش‌نمایش پارسی‌ورد را با همان پوستهٔ فشردهٔ ثبت‌شده در Git نگه دارد. ویرایش، ذخیره و Undo/Redo به TextDocument و تاریخچهٔ بومی همان سند متصل‌اند؛ یک تاریخچهٔ مستقل برای هر نما ساخته نمی‌شود. در نسخهٔ ۰.۱.۱ دو سمت مقایسه در دو گروه editor کنار هم باز می‌شوند تا فرمان بومی Undo به سند درخواست‌کننده برسد.

طبق درخواست کاربر، سازگاری میان‌برهای عادی VS Code هم معیار پذیرش ادیتور پارسی‌ورد است. این الزام برای ویرایش عادی و سمت قابل‌ویرایش مقایسه یکسان است؛ فرمان‌های ویرایشی روی نسخهٔ فقط‌خواندنی Git نباید متن را تغییر دهند و فرمان‌های عمومی میزبان باید به VS Code برسند.

دامنهٔ تأییدشدهٔ این مرحله شامل کپی/بریدن/چسباندن/انتخاب همه، حرکت و انتخاب متن، ذخیره، Undo/Redo، جست‌وجو، جایگزینی، رفتن به خط، Quick Open، Command Palette و جابه‌جایی تب‌هاست. انتخاب چند رخداد و چند مکان‌نما به درخواست صریح کاربر در این مرحله نیست. وضعیت هر میان‌بر باید با آزمون کلید و فوکوس واقعی منبع، پیش‌نمایش، کادرهای ورودی و نسخهٔ فقط‌خواندنی ثبت شود.

فرمان‌های عمومی میزبان و Clipboard از مسیر keybinding و webview بومی عبور می‌کنند. Find، Replace و Go to Line فرمان‌های مستقل پارسی‌ورد و binding قابل تنظیم دارند؛ روی متن منطقی منبع یا متن قالب‌بندی‌شدهٔ فعال عمل می‌کنند. شمارهٔ خط/ستون بر اساس Markdown تعریف می‌شود؛ در منبع، مکان‌نما دقیقاً انتخاب می‌شود و در پیش‌نمایش، بلوک متناظر منبع آشکار می‌شود. Undo در کادر جست‌وجو یا تنظیمات متعلق به همان کادر است و نباید سند Markdown را تغییر دهد.

در دو گروه کنار هم، فوکوس واقعی webview برای انتخاب مقصد فرمان گزارش می‌شود؛ `panel.active` به‌تنهایی ممکن است هنوز پنل قبلی را نشان دهد. این گزارش فقط مقصد فرمان را تعیین می‌کند و مالکیت سند و تاریخچه را عوض نمی‌کند. [نتیجهٔ آزمون نسخهٔ ۰.۱.۱](../validation/parsiword-git-comparison.md).
