# مرجعیت Markdown منطقی و حفظ منبع در ویرایش قالب‌بندی‌شده

متن منطقی Markdown جاری، مرجع سند پارسی‌ورد است؛ مدل ویرایش قالب‌بندی‌شده و درخت نحوی از آن مشتق می‌شوند. برای حفظ شیوهٔ نگارش نویسنده و جلوگیری از تغییرهای نامرتبط در منبع، قرارداد حفظ منبع درون بلوک و پاراگراف نیز برقرار است.

ویرایش متن یا قالب‌بندی باید نواحی نامرتبط منبع، شامل فاصله‌ها، escapeها و پایان سطرها را حتی در همان پاراگراف حفظ کند. تغییر ساختاری، مانند تبدیل پاراگراف به فهرست یا شکستن و پیوستن بلوک‌ها، می‌تواند کوچک‌ترین ساختار لازم را بازنویسی کند؛ متن خارج از محدودهٔ اثر آن باید حفظ شود. مشاهدهٔ سند، تغییر نما، فونت یا جهت نمایش نباید منبع را بازنویسی کند.

گزینهٔ محدودترِ حفظ فقط بلوک‌های دست‌نخورده و بازتولید کامل بلوک ویرایش‌شده در تصمیم کاربر رد شد، زیرا می‌تواند با ویرایش یک حرف، فاصله‌ها یا نشانه‌گذاری نامرتبط همان پاراگراف را تغییر دهد. برابری معنای Markdown به‌تنهایی معیار کافی برای این قرارداد نیست.

دامنهٔ قرارداد، متن منطقی جاری است؛ حفظ encoding اولیه یا برابری بایت‌به‌بایت با فایل ورودی تعهد آن نیست. سیاست صریح و موجود میزبان برای یکسان‌سازی پایان سطرها (EOL) همچنان مجاز است و حفظ نواحی منبع در چارچوب همان سیاست سنجیده می‌شود.

در متن عادی، پایان سطر نرم منبع در نمای قالب‌بندی‌شده و خروجی‌های Word و PDF مانند فاصله نمایش داده می‌شود. شکست صریح، مرز پاراگراف، پایان سطرهای کد و معنای فرمول‌ها حفظ می‌شوند. این سیاست نمایش و تبدیل، متن منبع را هنگام مشاهده بازنویسی نمی‌کند.

این قرارداد در ledger حفظ منبع و mutationهای ویرایشگر پیاده شده است. متن تازه‌وارد می‌تواند برای حفظ معنای literal از escape یا entity استفاده کند؛ حفظ دقیق به نواحی ازپیش‌موجودِ نامرتبط مربوط است. شواهد مستقل transaction، متن کامل، undo/redo و فایل خروجی در [جدول پذیرش](../markdown-contracts.md) و [وضعیت اجرا](../implementation-progress.md) ثبت می‌شوند؛ عبور fixtureها ادعای نبود تمام باگ‌های آینده نیست.
