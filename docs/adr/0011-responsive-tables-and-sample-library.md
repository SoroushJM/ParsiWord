# جدول خوانا و کتابخانهٔ نمونه‌ها

تأیید کاربر: ۲۰۲۶-۱۰-۲۹. ستون‌های جدول بر اساس محتوای رندرشده عرض
می‌گیرند؛ ستون کوتاه جمع‌وجور و متن بلند پس از سقف خوانایی چندخطی است.
رشته و پیوند بلند در نمایش می‌شکنند. جدول عریض فقط داخل قاب خودش افقی
اسکرول می‌شود؛ متن یا اندازهٔ قلم برای جا دادن جدول کوچک نمی‌شود.

فرمول عرض طبیعی خود را حفظ می‌کند. اگر از عرض قابل‌استفادهٔ پنل پیش‌نمایش
بزرگ‌تر باشد، در خانه با ScrollArea شادسی‌ان اسکرول افقی دارد. عرض واقعی
پس از رندر و تغییر فونت/عرض پنل مبناست. تصویر بزرگ با حفظ نسبت کوچک می‌شود.
این سیاست مربوط به نمایش و ویرایش مشترک وب، برنامه‌ها و VS Code است.

کتابخانهٔ نمونه‌ها ورودی کم‌جلب‌توجه در production دارد، با نمونه‌های آماده
و امکان ذخیره و حذف نمونهٔ شخصی روی همان دستگاه. هر نمونه فقط نام و Markdown
دارد؛ توضیح انتظار کنار مورد آزمایش داخل Markdown نوشته می‌شود. انتخاب نمونه
جایگزین سند فعلی و یک تغییر مستقل قابل Undo/Redo است، از جمله Undo بومی VS Code.
حالت آزمایشی جدا و توضیح انتظار در فراداده انتخاب نشدند.

کتابخانه یک ماژول تأخیری مستقل است. با `VITE_SAMPLE_LIBRARY=false` هنگام ساخت،
ورودی، کد کتابخانه و متن‌های آماده از خروجی حذف می‌شوند؛ فعال‌بودن آن به DEV
وابسته نیست. نمونه‌های شخصی با حذف قابلیت از خروجی پاک نمی‌شوند.

پیاده‌سازی نمونه‌ها در `packages/core/src/sample-library` و سیاست عرض در
ویرایشگر مشترک است. آزمون‌های `responsive-tables.spec.ts` و
`sample-library.spec.ts` در مرورگر توسعه و با
`playwright.production.config.ts` روی build واقعی اجرا می‌شوند. آزمون متمرکز
VS Code با `PARSIWORD_TEST_FOCUS=sample-library`، Undo/Redo بومی و نگهداری
نمونه پس از بستن webview را بررسی می‌کند. اسکریپت
`check-sample-library-build.mjs` حضور/حذف واقعی chunkها و متن‌های کتابخانه
را در حالت فعال و غیرفعال بررسی می‌کند.
