# حفظ جدول نامنظم و اصلاح صریح آن

تأیید کاربر: ۲۰۲۶-۱۰-۲۹. جدول نامنظم جدولی است که تعداد خانه‌های حداقل
یک ردیفش با هدر متفاوت است. خانه‌های اضافه در پیش‌نمایش قابل‌ویرایش
دیده می‌شوند؛ نمایش یا ویرایش متن نباید آن‌ها را حذف یا جدول را خودکار
یکدست کند. این انتخاب عمداً از نمایش GFM که خانه‌های اضافی بدنه را
نادیده می‌گیرد و از اصلاح خودکار ویرایشگر جدول متفاوت است.

- افزودن و حذف ستون تا زمان یکدست‌شدن جدول غیرفعال است.
- افزودن و حذف ردیف فعال می‌ماند. ردیف جدید دقیقاً به تعداد خانه‌های
  **هدر** خانهٔ خالی دارد، حتی اگر بدنه ردیفی بلندتر داشته باشد. این
  عملیات نباید ردیف‌های دیگر را کامل کند.
- دکمهٔ «کامل‌کردن ستون‌های جدول» فقط در ابزارهای جدول نامنظمِ انتخاب‌شده
  ظاهر می‌شود و فقط همان جدول را تغییر می‌دهد.
- اصلاح، تعداد ستون‌ها را برابر بلندترین ردیف با احتساب هدر می‌کند.
  خانه‌های کم‌شده به انتهای منطقی ردیف‌ها در سورس اضافه می‌شوند؛ هدر و
  خط جداکننده نیز کامل می‌شوند. خانه‌ها و عنوان‌های جدید خالی‌اند.
- هیچ محتوایی حذف، جابه‌جا یا بر اساس معنایش حدس زده نمی‌شود. برای مثال
  `| سارا | شیراز |` با اضافه‌شدن خانهٔ سوم به `| سارا | شیراز | |`
  تبدیل می‌شود؛ تشخیص اینکه سن جا افتاده است بر عهدهٔ نویسنده می‌ماند.
- پس از اصلاح، دکمه پنهان و ابزارهای ستون فعال می‌شوند. یک Undo کل اصلاح
  را با منبع اولیه برمی‌گرداند؛ Redo نیز همان اصلاح را تکرار می‌کند.

سیاست در ویرایشگر مشترک وب، VS Code و برنامه‌های بومی یکسان است.
اصلاح همهٔ جدول‌های سند، حدس محل خانهٔ گمشده و حذف خانه‌های اضافه انتخاب
نشدند؛ تغییر ساختاری باید صریح، محلی و بدون از دست‌رفتن داده باشد.
